Existing MC68010 sdcard.o DWARF (NOT generated by a new build) records GNU C11
13.3.1, pointer size4, bool size1, enum size4, SDCard size22, initialized@0,
type@2, reserved[4]@6. Relevant output is preserved in evidence/. Our descriptor
is _Alignas(2) byte[22], with static size/alignment checks, and explicit big-endian
type extraction at offset2. Thus host tests use the target wire-memory layout,
not native Linux bool/enum padding. This proves compatibility with the inspected
public-layout artifact, NOT identity of the active ROM. No fshort-enums/mshort ABI
is supported; future target checks must verify the actual ABI consistently.

D0.L selector and return. D0/A0 scratch. Init A1=descriptor; sector A1=descriptor,
D1=LBA,A2=512B buffer; register A1=descriptor,D1=9,A2=16B buffer. Firmware permits
clobbering argument registers. C-callable wrappers preserve A2 when used and the
other saved argument registers; D2-D7/A2-A6 must retain normal GCC callee-saved
semantics. Support only uses D0/A0. Init saves8 bytes -> arg1@12(sp). Read saves16
-> descriptor@20, LBA@24, buffer@28. CSD saves16 -> descriptor@20, buffer@24; CMD9
is an immediate, never a caller argument. Plain RTS returns raw D0; C bridge
normalizes boolean nonzero firmware results to callback int1/0. No ABI casts.

src/sd_ro_traps.S uses only MC68010-compatible source mnemonics moveq/move.l/
movem.l/trap/rts. Source audit checks exact instruction sequences, selectors and
stack offsets, but does NOT assemble or validate emitted machine code. New wrappers
must be target-compiled/disassembled in a separately authorized phase.

Known firmware false-OK: bbsd.c initializes result=OK; CMD58 failure at68-69 can
jump to cleanup before initialized/type assignment. Adapter clears descriptor
first and requires initialized==1 plus known type in addition to status0.

Data/register APIs report only boolean success, not partial count. Firmware reads
16 CSD bytes plus consumes two unvalidated CRC bytes; block read takes512 then
ignores CRC. Init sends CMD59 to disable CRC. No firmware patch is introduced.
SDSC block<<9 lacks overflow guard: our checked guard precedes every read.

No legacy SD object is reused: original sdcard_asm.o contains a write wrapper.
Host profile links only core C and mocks; target .S is NOT included. Firmware
implementation, libtermios, Newlib, FAT and installed librosco are not linked.
